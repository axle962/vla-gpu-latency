VLA Latency Project Status

What we did since 11 Nov: new robot policies, benchmark and side studies, the final cross-GPU model, and task-success tests in simulation. Four GPUs: A100 (cluster), RTX 2080 Ti, TITAN V and RTX 4070 (CIMS).

Main points

Three latency regimesDispatch bound (SmolVLA, pi0, pi0.5), mixed (ACT) and GPU bound (Diffusion Policy). CUDA graphs help a lot only in the first.
GPU order flips between modesThe 4070 is slowest in eager mode and fastest with graphs. The host CPU sets eager speed.
The model predicts the flipslot_drv ranks the four GPUs correctly in 65% of SmolVLA cases, against 27% for memory-bandwidth scaling.
Faster inference can raise task successOn LIBERO-Long, graphs move pi0.5 on the 4070 from 65% to 76% success. On RoboTwin's hammer task, delay did not matter.

Reactor (Praxis-1)

Logged on 11 Nov as outside evidence only; we ran no experiments on it. Their B200 inference spent 249 of about 800 ms in Python, and they cut kernels from 21,740 to 4,944. This supports our finding that framework dispatch, not the GPU, sets eager latency.

Benchmarks and side studies

StudyResult
Batch sizeEager stays flat (host bound); the graph loop grows. Graph speedup falls below 2x at batch ~10 (TITAN V), ~16 (2080 Ti), above 16 (4070). Cross-GPU error 6 to 18% up to batch 8, 27% at batch 16.
torch.compileFuses ~11.5k kernels into ~3.2k. Compiled plus graphs is ~2x faster than our hand-built graph (2080 Ti 20.8 vs 40.1 ms). Cross-GPU error 12% at batch 1.
EnergyGraphs cut GPU energy per inference 1.6 to 2.7x at batch 1 (4070: 31 J to 11.5 J), 1.1 to 1.5x at batch 8.
Calibration ablationSpec sheets only: eager error 34%, graph loop 38%, correct ranking 20%. The PyTorch dispatch table and the graph-slot table carry most of the gain.
Host CPU experimentCPU contention on one 2080 Ti slows eager 1.65 to 1.93x; the graph loop stays within 8%.
RodiniaOur rules fail on throughput kernels (~100% error); bandwidth-bound streamcluster within 2.5%.
What-if (spec only)H100, H200, L40S, RTX 4090, PRO 6000 from A100 traces. Eager OpenVLA barely moves (dispatch bound). The H200 being slower than the H100 in public benchmarks points to host or software, not the GPU.

RoboTwin 2.0 (A100 cluster, SmolVLA)

  • beat_block_hammer: 63 / 63 / 70 / 73% success at 0 / 120 / 400 / 800 ms delay. A control that replans at the same points with no delay gives the same result, so staleness costs nothing here; the small gain comes from replanning more often.
  • lift_pot: delay study in progress (0 ms, 800 ms and the replanning control, 100 episodes each). Done so far: 0 ms at 37 of 76 episodes (49%), control 12 of 28. Five blocks lost to failed node boots were resubmitted.
  • SmolVLA's RoboTwin checkpoint has the same latency as the base model (eager 378 ms, graph loop 35.4 ms).
